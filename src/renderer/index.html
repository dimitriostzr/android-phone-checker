What it is

Phone Checker runs read-only security and privacy checks on your own Android phone over ADB, and proposes changes you review and approve one at a time. Standard, documented commands only. No root, no exploits, no telemetry, no account.

Why I built it

It started with an actual incident: a preinstalled, system-privileged app store put apps on my phone that I never asked for. What stuck with me was how little an ordinary owner can see about their own device. I packaged up the checks I had been running by hand, and published them because other people might find them useful too.

What it is not

  • Not a malware scanner. The tripwire check compares against a small list of publicly documented package names. A clean result only means "nothing on that list".
  • "All clear" is not proof the phone is safe. It means these checks found nothing over ADB, which sees only what Android exposes. A check that cannot read what it needs is reported as unreadable, never as a pass.
  • Not a forensic or certification tool. It helps you look at your own phone and make reversible changes you agreed to.

Use with care

These are real commands on a real phone. Every change made here can be undone from History, but a package that is harmless to disable on one model may matter on another, and the Terminal runs exactly what you type. Read what an item does before approving it, and use Search web if you are unsure. What you approve is your decision, and the result is your responsibility.

Safety model

  • The app never changes anything on its own. Every write waits for a confirmation dialog that lists each affected item.
  • The previous state is saved first, and every applied change is recorded in History so you can undo it.
  • Caution items, settings with trade-offs and system apps ask a second time, spelling out what breaks. Keep-tier packages can never be selected.
  • In the Terminal only commands recognised as read-only run straight away. Anything else asks, destructive commands ask twice, and an unknown command counts as a write.
  • The window drawing this page has no access to your computer: context isolation is on, Node integration is off, and a default-src 'self' policy stops the page loading anything from the network. It can only call the named operations listed in Commands it runs, each handled in the main process.

⚠️ Read this before you start

Phone Checker inspects your phone over ADB and, only when you explicitly ask it to, makes deep but standard changes: disabling preloaded apps and adjusting system settings.

Use at your own risk

Phone Checker is a free, open-source tool provided as-is, without warranty of any kind. Whether to use it, and what to approve in it, is your decision, and what happens on your phone as a result is your responsibility.

Back up your phone first

Before you approve any change, take a full backup if you possibly can. Nothing here is meant to lose data, but a backup is what turns a bad surprise into an inconvenience.

Use your phone maker's own backup tool over USB where there is one (Smart Switch on Samsung, for example), or your cloud backup, and check your photos and messages are included. A backup you have tested restoring is worth more than one you have not.

  • This is not rooting, jailbreaking or bootloader unlocking — nothing of that kind is attempted or possible here. Every change uses Android's documented user-level commands and is reversible from History.
  • Deep edits still deserve care: disabling the wrong package can break features. Read each item and research anything you are unsure about before approving it.
  • Items marked caution or trade-off always ask for a second, separate confirmation that spells out exactly what breaks.
  • The Terminal lets you run adb commands you type yourself. Read-only commands run straight away; anything that could change the phone asks for confirmation first and destructive ones ask twice — but a command you type is not undoable from History.
  • Only use Phone Checker on a phone you own or are authorized to manage.

Before you close

A quick safety checklist — for every phone you worked on in this session:

  • USB debugging — turn it off now that you are done (leave it on only if you know you still need it). The button below does it for the connected phone; on any other phone, or if the button cannot, it is Settings → Developer options → USB debugging.
  • Protections you paused — re-enable anything you switched off to use adb tools, for example your device brand's app-security guard (called Auto Blocker on some phones).
  • Changes you approved — package disables stay reversible from History any time; nothing else needs undoing.
  • Developer options — turning USB debugging off leaves Developer options itself switched on. The toggle at the top of that screen turns the whole thing off.
